# 事件模型计算约定

时间使用从开班起算的秒。第 b 格的整批投料在 (b−1)×1800 秒可用，订单截止为 b×1800 秒。每件产品依次加工、装配、初测，初测失败后最多返工一次，修好必须复测，修不好即报废。相邻操作间有固定转运时间。测试开始时确定缺陷概率（恰在冲击时刻使用新概率），结果在测试完成时揭晓。每件使用 CSV 中自己的缺陷和修复抽数。

同一秒先处理全部完工与发货、投料和转运到达，再根据当前班次派工。最早截止订单先发，相同截止按订单 ID；截止瞬间最后一件发出算准时。各队列先到先做，复测优先于初测。每名工人一次做一件。正常班次结束瞬间可完工，不再开始正常班工作。继续方案随后冻结在制品。调配方案冲击后将一名装配工转到测试，当前任务做完才移动。允许全线加班时，自班末起连续计费，最后一张订单完成或满两小时即结束（观察期更短时以观察期为限）。停线时尚在加工的件仍算 WIP。机动工在冲击后每半小时先测试15分钟再返工15分钟，仅在当前工作段内能完成时接单。

事件设置表列出合成工人数量与每件服务秒数。装配固定工和可调工的速度可不同；每半小时理论名额为各工人 1800 / 服务秒数之和。采用独立并行工位和充足工具，转运不另占工人。固定工资是全线费用，具名工位仅表示限制产能的资源。以上是模拟假设，工厂适用性未经验证。

每个时刻投入 = 已发货 + 已报废 + 合格库存 + 在制品（排队、服务中、转运中）。成本按基础工资、机动工排班小时、全线实际加班小时、返工完成数、报废件数、晚交或未交订单数、期末 WIP 分别计费，费率取 costs.csv。

手算验收：零转运、无缺陷，四件同时投料，三个工位各一人，每件各用 2、3、1 秒。加工完工在 2/4/6/8 秒，装配在 5/8/11/14 秒，发货在 6/9/12/15 秒。两单各两件，分别要求第9及15秒交齐，均准时；无加班、返工、报废及积压，总成本等于基础工资 2400 美元。

默认每次转运为60秒。可调工支援测试时每件900秒，机动工测试和返工均为每件900秒。固定装配工每件360秒，可调工每件900秒，合计每半小时 5+2=7 件。每站并行资源数量和每件秒数分别决定产能及首件交付时间。

从仓库根目录运行 `python3 -B -m python.event_sim` 查看三个方案。运行 `python3 -B -m unittest discover -s tests_py -v` 复核手算例和边界。调用 simulate_day 后可检查 result.log，各行依次为秒数、产品编号、事件、工序或订单、工人。result.orders 保存各订单交齐的秒数。
